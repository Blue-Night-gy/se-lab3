# 界面设计与功能说明

我把顾客端排成客房目录, 酒店端排成横向工作台. 顾客需要先看清住宿和费用, 前台则需要连续核对日期, 状态和房号. 两种页面共用木色按钮和米色背景, 各自保留合适的信息密度. 界面里的酒店, 人员, 日期和金额均为贯穿设计的样例数据.

主参照是[MUJI HOTEL GINZA客房页](https://hotel.muji.com/ginza/en/rooms/). 我实际查看了房型介绍的图文分区: 左侧写房型与条件, 右侧留大幅实景, 区块之间靠留白区分. 查询页和房型页沿用这个阅读顺序, 再加入城市, 住宿日期, 人数, 间数和价格条件. 摄影来自Unsplash, 来源单独列在design/assets/sources.json, 没有复制参照网站的酒店照片.

初版采用蓝白色和较多卡片. 收到"蓝黑白色太难看"的反馈后, 我重新找了参照并重做版式, 而后确认保留当前木色, 米色方案. 前台去掉大块指标卡, 用待确认, 当日入住, 在住和待协调分组连接订单表. 订单详情用逐晚明细说明金额, 提示只解释当前动作会带来的结果.

| 界面 | 功能和操作 | 需要看清的设计点 |
| --- | --- | --- |
| UI-01 账号与身份入口 | 顾客, 酒店人员和管理员的入口, 含注册入口 | 授权来自账号, 页面选择不能产生酒店权限 |
| UI-02 多间连住组合查询 | 城市, 入退日期, 人数, q间, 房型及价格组合查询 | 筛选按每间每晚, 每个住宿夜均满足; 另显示q间全程总价与全程可售量 |
| UI-03 房型与全程可售量 | 查看酒店和不同房型, 选择可容纳人数与间数的住宿 | 图片对应房型; 可订量是住宿夜最小余量, 退房日不占用 |
| UI-04 两间三晚预订 | 填写入住信息, 核对三晚价格后提交 | 260/280/310各乘2, 共1700元; 待确认即占每晚2间 |
| UI-05 价格变化与再次接受 | 比较原价1700和新价1780, 选择接受或返回 | 标出首晚260变300及总差80; 等待接受时不新增占用 |
| UI-06 我的预订列表 | 查看本人不同状态的行程并进入详情 | 状态和日期同时呈现, 保留取消及已完成记录 |
| UI-07 订单详情与确认期限 | 查看状态, 逐晚成交价, 入住人, 政策和可用操作 | 待确认截止精确到秒; 成交明细不随日售维护自动变化 |
| UI-08 日期房型与间数调整 | 对比原行程和新行程, 接受重算费用 | 6日至9日改7日至10日, 总价1760; 逐夜差额为-2/0/0/+2, 成功后新截止10:30 |
| UI-09 仅更正入住人 | 单独更正姓名和联系方式 | 保存后仍为原1700元和原10:20截止, 不重开20分钟 |
| UI-10 免费取消与18点截止 | 取消前再次核对当前行程和截止, 显示取消结果 | 当日18:00或实际入住取较早截止, 取消释放全部住宿夜的q间 |
| UI-11 前台订单处理 | 按当前计划入住日和状态筛选, 确认或进入到店办理 | 列表不用下单日归档, 住宿调整后立即按新计划入住日归属 |
| UI-12 多房号整体分配 | 为两间订单选择201和202并一次办理入住 | 必须恰好q个不同同店同型空闲房, 任一不合规整体拒绝 |
| UI-13 整单退房与待清洁 | 核对全部活动房号, 一次完成退房 | 201与202同时转待清洁, 不直接恢复可用房态 |
| UI-14 房量房价日历 | 按房型和日期维护售价, 房量与停售 | 每日余量和已占用分别显示, 总量不能调至低于已占用 |
| UI-15 客房清洁维修看板 | 查看空闲, 已入住, 待清洁, 维修状态并处理 | 入住和退房后的房态随跨页样例变化; 清洁完成后才转空闲 |
| UI-16 停业日期与异常协调 | 设置明确停业范围, 核对受影响旧单和处理记录 | 保留原因, 联系情况, 处理人和结果, 不自动删单或越过修改期限 |
| UI-17 酒店房型维护 | 维护本酒店房型名称, 容量和资料 | 房型资料与每天售价分开, 唯一编号不随展示名称改变 |
| UI-18 平台酒店名录 | 管理员查询和维护酒店, 查看售卖状态 | 城市和酒店范围清楚, 停业仍保留原资料及历史订单 |
| UI-19 账号与独立日志授权 | 管理员维护账号, 酒店管理和日志查看权限 | 维护酒店不自动拥有日志权, 授权按酒店分别授予 |
| UI-20 住宿区间与间夜统计 | 管理员按城市, 酒店和日期查询列表与统计 | 列表按当前入住日, 统计按住宿交叠; 取消计笔数但有效间夜为0 |
| UI-21 多条件操作日志查询 | 同时按酒店, 时段, 对象, 人员与结果筛选并看明细 | 前后值与失败尝试分开, 人员权限变更日志只给管理员 |
| UI-22 同程新请求的继续或放弃 | 展示已有待确认/已确认的同程订单, 再决定是否新增 | 比较酒店, 房型, 入退日, q五项; 改姓名仍提醒, 决定前不占新库存 |
| UI-23 售罄到期与权限反馈 | 展示售罄, 超时, 18点截止和他人订单拒绝 | 给出返回查询或本人订单的入口, 不展示他人订单内容 |
| UI-24 工作人员日志权限拒绝 | 夏宁有酒店维护权但无该酒店日志权时拒绝 | 仍用酒店工作台外壳, 不呈现任何日志正文 |

24张完整PNG保存在UI界面目录. 图册中较长的查询页和房型页分段放大, 避免整页缩到看不清文字. 本地预览用于查看页面与样例状态跳转, 表单展示不等于已实现的数据库服务.
