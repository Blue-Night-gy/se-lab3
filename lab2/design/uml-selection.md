## UML类型与本项目的取舍

我按课程要求将图分成结构, 行为和交互三组. 类图是必画图, 另外选择包图说明依赖, 对象图核对两间三晚的实例, 状态图检查期限, 活动图表达接受决定的循环, 时序图检查事务竞争, 部署图交代存储与运行环境. 共8张, 7种, 不把两张时序图重复算作两种类型.

| 类型 | 主要描述内容 | 本项目的选择理由 |
| --- | --- | --- |
| 类图 | 类, 字段, 方法, 关联与组合 | B02必画, 展示私有状态和受控修改, 区分订单拥有的子记录与独立资源 |
| 对象图 | 特定时刻的对象实例和链接 | B03用1700元订单和两个房号验证类图中的关系是否能落到实例 |
| 组件图 | 可替换组件及其提供, 依赖接口 | 本轮是单应用, 用包图表达模块依赖更直接; 后续拆进程或替换适配器时可补充 |
| 复合结构图 | 一个分类器内部的部件, 端口及连接 | 核心问题在跨订单, 日售和实体房的一致性, 暂无复杂内部端口结构需要展开 |
| 部署图 | 软件制品与运行节点的部署关系 | B08交代应用, MySQL, 客户端与持久任务, 对应性能验收环境 |
| 包图 | 命名空间或模块分组及依赖 | B01区分接口, 应用, 领域, 端口与基础设施, 解释依赖方向和事务职责 |
| 剖面图 | 用构造型等方式扩展特定领域的UML表达 | 目前普通UML元素足够, 无需另外定义酒店行业剖面 |
| 活动图 | 动作, 分支, 循环和控制流 | B05表现新价接受, 同程继续和放弃, 强调真正返回提交入口 |
| 用例图 | 参与者和系统对外提供的目标 | 三种角色和功能已在需求及本报告功能说明中明确, 本轮更需要状态与事务细节 |
| 状态图 | 一个对象的状态及事件守卫 | B04直接检查五状态, 20分钟到点和入住日18点截止 |
| 通信图 | 参与交互的对象连接及编号消息 | 可表达协调服务与资源关系, 本轮改用时序图突出等待锁和读取最终时刻的先后 |
| 交互概览图 | 多段交互之间的高层控制流 | 核心流程已有B05活动图及B06/B07时序图, 暂不重复增加总览层 |
| 时序图 / 序列图 | 生命线之间按顺序发生的消息 | B06新建及重发, B07改单与超时, 两个名称在本报告按Sequence Diagram同一种计数 |

UML记法依据[OMG UML 2.5.1](https://www.omg.org/spec/UML/2.5.1/About-UML), 图源使用[PlantUML官方语法](https://plantuml.com/). 图中的包和聚合表达职责与依赖, 不直接把每张数据库表等同为一个业务类.
